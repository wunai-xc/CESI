## 完整的 MDX 文件头

文章支持 `.mdx`（可写 JSX/组件）和 `.md`（纯 markdown）两种扩展名，两套 frontmatter 完全一样。
新建文章时，把下面这段直接抄到 `src/app/content/posts/<slug>.mdx`（或 `<slug>.md`）最顶部（`---` 必须是文件第一行）：

````mdx
---
title: 文章标题
date: "2025-10-31"
summary: 一句话摘要，会出现在文章列表和页面的 description 里
tags: [Next.js, MDX]
draft: false
---

## 正文从这里开始

普通的 markdown 内容都可以写在这里。
````

各字段的含义：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `title` | 必填 | 文章标题，列表页和详情页的 `<h1>` 都用它 |
| `date` | 必填 | `YYYY-MM-DD` 字符串（带引号），决定排序和「上一篇 / 下一篇」；位数不补零（`2026-11-1`）也会自动补成 `2026-11-01` |
| `summary` | 可选 | 列表页摘要 + `generateMetadata` 的 description |
| `tags` | 可选 | 写成 `[A, B]` 数组，也可以写 `A, B、C` 这种分隔字符串；会生成标签页 |
| `draft` | 可选 | 写 `true` 就是草稿：**dev 下正常显示**（标题旁有 `draft` 标记），**构建时整篇排除**，不会出现在线上 |

注意事项：

- 文件头里的键名区分大小写，写 `Title` 或 `Date` 都会被认为缺失，构建时会打印 `[posts] 跳过 xxx.mdx` 警告并**跳过这篇文章**（不会让整站崩掉）
- `date` 忘了写引号会被 YAML 解析成日期对象，本项目已兼容这种情况，但仍建议统一写成 `"2025-10-31"`
- MDX 文件里不要写注释，文件头必须以 `---` 开头
- 值里出现冒号加空格（比如 `summary: 用 draft: true 标记…`）会让 YAML 解析失败，请用引号包起来：`summary: "…"`；解析失败只会跳过这一篇并打印警告，不会崩站
- 另一种草稿方式是文件名以 `_` 开头（如 `_草稿.mdx`），这类文件完全不会被读取
